## C++ / CMake persistence clarification

The authoritative user-project representation is the normal capability model:
`capabilities.languages` / `environment.language` for C++, and
`capabilities.buildSystems` / `environment.buildSystem` for the build-system
selection. The current saved self-host project contains `cpp` and `cmake`, and
the production GUI restored both after reopen. `aramf-profile.json` is product
profile metadata generated by ARAMF; its `implementationLanguage: C++17` and
`buildSystem: CMake` describe ARAMF itself and are not the project-selection
record.

## Resource authority persistence

SELFHOST-ISSUE-002 was reproduced through the real GUI: authority selections
could appear correct while the authority page was open, but some selections
returned to `supporting-reference` after Save/Reopen. Project persistence
already serializes `ProjectResource.id`, `authorityLevel`, `description`, and
`scopes`; the production correction makes inventory and authority UI binding
ID-based and preserves the selected resource ID across refreshes. Automated
round-trip coverage now verifies authority, description, scopes, and resource
reordering. Final GUI matrix verification remains required before declaring
the self-host configuration complete.
