## What is known

Substantial ARAMF development activity occurred during July 2026. No
surviving July 2026 Git commits have currently been identified. The absence of
surviving commits must not be interpreted as evidence that development did not
occur.

The original local ARAMF/Pico Visual Designer development environment was
later lost when the disk partition containing the projects was accidentally
deleted during AI-assisted development. Local source code, uncommitted work,
generated artifacts, Git metadata, and possibly local-only commit history may
therefore have been lost.

ARAMF was later substantially reconstructed. Surviving development
conversations and later project state provide evidence that ARAMF development
was active during July. The later reconstructed architecture is evidence of
the direction and recovered state of the project; it is not proof that every
later implementation detail existed in July.

## Evidence integrity

This record distinguishes three evidence levels:

1. Directly preserved evidence consists of the repository state, files, and
   Git metadata that survived and can still be inspected.
2. Conversation-derived evidence consists of surviving development
   conversations describing work, decisions, intended behavior, and project
   direction.
3. Reconstructed historical context consists of cautious inferences from
   those sources and from later project state.

Where certainty is limited, this document uses the latter two categories
explicitly. No missing commit is fabricated, and no reconstructed detail is
presented as preserved July source code.

## Development direction indicated by surviving records

Surviving development records indicate that ARAMF was being developed as a
framework for configuring and managing projects across multiple technology
and target contexts. Available conversation history shows activity around:

- project configuration and a structured project model;
- project languages, frameworks, SDKs, development tools, target platforms,
  hardware, and architecture;
- build, test, and delivery concepts;
- project generation and generated project structures;
- governance, rules, project state, and validation;
- AI-agent responsibilities and agent-facing instructions.

The later reconstructed architecture suggests that these concerns were being
organized as reusable, project-aware ARAMF configuration and generated
control-plane material. No surviving source-code state is available to confirm
the exact implementation, file layout, or commit sequence for July 2026.

The surviving record also supports a relationship between ARAMF and Pico
Visual Designer: ARAMF was used as the framework or project-management context
for work associated with that separate project. Pico Visual Designer is a
separate historical subject and must not be treated as part of ARAMF's source
history. It is mentioned here only to explain the relationship and the loss of
the shared local development environment.

## Purpose and limits

No source code is being reconstructed by this documentation commit. This file
exists only to preserve project history and explain the gap in Git history.
It records that July development was active, identifies the loss of the
original local environment, and separates preserved evidence from
conversation-derived and reconstructed context.
